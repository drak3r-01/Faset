# Lot 4.9 — Bots: navigation graph and pathfinding
- Model/effort: Sonnet, high | Depends on: 4.3 | Milestone: none

## Goal
Generate the navigation graph automatically from a loaded map (walk, fall, jump, jump pads, teleporters) and provide A* pathfinding with path smoothing. The same graph later serves the map validator's accessibility test.

## Crates
- Owned: `bots` (graph builder, A*, path smoothing, public API `NavGraph`).
- Read-only: `sim` (character controller, collision queries, capsule sweeps: must be used for jump simulation), `mapfmt` (map zones, spawn points), `minigame-api`, `core`.
- Forbidden: public interfaces of `sim`, `mapfmt`, `minigame-api`, `core`. If the controller needs a parameter it does not expose, stop and report.

## Spec
### Graph construction (automatic at map load, no manual annotation)
1. Sample the map in cells of 0.5 m. A cell is walkable if the capsule (radius 0.35 m, height 1.8 m) fits standing on a floor there.
2. Link two neighbouring walkable cells if the step height is at most 0.45 m and the slope is walkable.
   Walkable floor: surface normal n_y >= 0.707 (same threshold as the controller).
3. Drop edges: where a ledge gives onto a lower floor (no jump needed).
4. Jump edges: simulate the real character controller with a jump command (jump speed 6.5 m/s, gravity 20 m/s^2, run speed 7.0 m/s, ground friction 6 s^-1, ground acceleration 10 s^-1, air cap w_air 0.8 m/s). An edge exists only if the simulation lands on a walkable cell.
5. Jump pad and teleporter edges, taken from the map's zones (jump pads: the launch vector from the zone; teleporters: the destination).
Jump apex for reference: v_j^2/(2g) = 1.06 m; airtime 0.65 s; run-speed jump range 4.55 m.

### Pathfinding
A* over the graph. Cost g = travel time along the edge. Heuristic h(n) = |p_n - p_goal| / v_max, with v_max a configured constant that must be >= the fastest speed the planner can produce (so h stays admissible); report the value chosen.
Smoothing: remove intermediate waypoints whenever the straight line between the surrounding points is walkable.
Re-plan every 0.5 s and whenever the goal changes.

### Accessibility use
Expose a query for the validator (lot 5.x): reachable set from a point, and whether all spawn points are mutually reachable.

## Public interfaces to create or respect
- `NavGraph::build(map: &MapData, controller: &ControllerParams) -> NavGraph` (pure, deterministic, no GPU).
- `NavGraph::find_path(from: Vec3, to: Vec3, vmax: f32) -> Option<Path>` and `NavGraph::reachable_from(p) -> ReachableSet`.
- `Path` holds waypoints with edge kinds (walk, drop, jump, pad, teleport). Types are `glam` Vec3, metres, seconds.

## Acceptance criteria
- `cargo xtask test`:
  - `example_map_accessibility`: on the sample map (from lot 3.x), every spawn point is reachable from every other; the test prints the reachable cell fraction (record it in the report).
  - Ledge test: a 0.45 m step is linked, a 0.46 m step is not.
  - Slope test: a surface with n_y = 0.70 is rejected, 0.71 accepted.
  - Jump edge exists only if the simulated landing is walkable (one positive and one negative case).
  - A* returns the shortest-time path on a small hand-built graph; smoothing removes collinear waypoints.
  - Graph build time on the sample map is printed; no test fails on time, the number is reported.
- `cargo xtask ci` is green.
