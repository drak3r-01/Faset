# Lot 7.3 — English documentation, release notes, tag v0.1.0
- Model/effort: Haiku, low | Depends on: 7.1, 7.2 (plan gives no explicit list) | Milestone: none

## Goal
Documentation in English is complete, and tag `v0.1.0` publishes the release through the pipeline.

## Crates
- Owned: documentation (`README.md`, `docs/`, rustdoc comments of public items if missing), workspace version field.
- Read-only: all code. No behaviour changes.
- Forbidden: changing public interfaces.

## Spec
Documentation (all English):
- player guide: controls, settings, hosting and joining on LAN;
- server guide: `server.toml`, CLI options (`clap`), console commands `status`, `kick`, `map`, `say`, `quit`, Docker image `server-runtime`; game port UDP 7777, LAN discovery UDP 7778; internet play needs manual port forwarding (no master server, no NAT traversal);
- developer guide: crate map (section 4), Docker commands (`dev.ps1`, `xtask` commands), map format pointer, mod-free scope;
- every public interface documented in English.

Release (section 3 and section 20):
- workspace version = `0.1.0`; tag `v0.1.0` must match it (the pipeline checks this).
- Push the tag: `release.yml` runs test (`xtask ci`), then build (six targets; four in Docker, two on macOS machines), then release (GitHub release with archives, checksums, notes generated from Conventional Commit messages, and the `server-runtime` image published to the GitHub container registry).
- A failing step stops the rest; no release if a test fails.
- Licence: the plan leaves the licence open ("to choose before public release"). If none is chosen, stop and ask before tagging.

## Public interfaces to create or respect
- None created. Documented as they are.

## Acceptance criteria
- `dev.ps1 ci` passes.
- Workspace version reads `0.1.0`; no other version strings disagree.
- No French text remains in the repo except the French translation file (lot 6.5).
- After the tag push: pipeline green; `gh release view v0.1.0` lists the archives, the checksum file and the notes; the `server-runtime` image is in the registry.

## Out of scope
- Features, fixes, signing, installers, internet directory, music.

## Session protocol
1. Read `CLAUDE.md` and this file.
2. Do not use graphify until the repo contains Rust code; then query it (`query_graph`, `get_neighbors`, `shortest_path` tools of the `graphify` MCP server) before grepping.
3. Branch `lot/7.3-docs-release-v0-1-0`. All commands run in Docker (`dev.ps1 <cmd>`), never on the host; `gh` is used on the host for GitHub release checks only.
4. Run `dev.ps1 ci` (= `cargo xtask ci`) before merge; it is the only quality gate.
5. Conventional Commits in English; one lot = one branch = one PR; run the graphify MCP graph refresh (if the MCP exposes one; otherwise say so in the report) once code exists.
6. Short report: delivered, tests passed, deviations from this file.

Conventions: repo content in English; `thiserror` in libraries, `anyhow` in executables, `tracing` for logs.
