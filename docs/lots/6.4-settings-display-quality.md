# Lot 6.4 — Settings: structure, metadata, persistence, display and quality
- Model/effort: Sonnet, medium | Depends on: 6.1, 2.10 | Milestone: none

## Goal
One settings structure, described by metadata from which the menu is generated; display and quality settings apply without restart.

## Crates
- Owned: `core` (settings module: schema, TOML persistence, migration), `ui` (settings menu generated from metadata).
- Read-only: `render`, `upscale` (apply via existing interfaces, including the `Upscaler` trait from lot 2.10), `audio`, `client`.
- Forbidden: changing public interfaces of read-only crates.

## Spec
- Single `Settings` struct. Each field has metadata: category, label key (translated, lot 6.5), type, range or options, default, apply mode (`Immediate` or `Restart`; this lot uses `Immediate` only).
- The menu is generated from the metadata.
- File: `settings.toml` in the OS configuration folder, with a version number; load migrates older versions; unknown keys ignored.
- Categories and fields:
  - Display: window mode, resolution, monitor, vsync, FPS cap, field of view, brightness.
  - Quality: render scale, upscaler and level, sharpness, anti-aliasing, shadows, occlusion, bloom, outlines, weather density, screen effects, draw distance.
- Upscaler interface, read-only, from `upscale` (section 11):
```
pub trait Upscaler {
    fn render_extent(&self, display: Extent2D, quality: Quality) -> Extent2D;
    fn jitter(&self, frame_index: u32) -> Vec2;
    fn execute(&mut self, ctx: &mut FrameCtx, inputs: &UpscaleInputs) -> ImageHandle;
}
```
- A resolution change asks for confirmation within 15 s; otherwise it reverts.
- Launch option `--safe` resets display settings to defaults (applied before loading the file).
- Upscale levels (factor per axis): Quality 1.5, Balanced 1.7, Performance 2.0, Ultra Performance 3.0. Free render scale from 50 % to 100 % for native and FSR 1 only.
- At startup the game detects available upscalers and offers only usable ones; on failure it falls back to FSR 1.

## Public interfaces to create or respect
- `core`: `Settings`, `SettingMeta`, `ApplyMode`, `load_settings(path) -> Settings`, `save_settings`.
- `ui`: `build_settings_menu(&Settings) -> Menu` generated from metadata.
- Apply function returns the list of changed fields applied immediately.

## Acceptance criteria
- `dev.ps1 test` passes:
  - every display and quality field has metadata and appears in the generated menu (test iterates the metadata);
  - changing each field calls the apply path with no restart (tested through the apply function result);
  - TOML round trip; an old version file migrates to the current version;
  - a resolution change reverts after 15 s without confirmation (simulated clock);
  - `--safe` resets the display fields only.
- `dev.ps1 ci` passes.

## Out of scope
- Controls, audio, network, game, accessibility settings (lot 6.5); translations of labels (lot 6.5).
