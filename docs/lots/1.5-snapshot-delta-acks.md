# Lot 1.5 — Delta snapshots, acknowledgements, reference frames
- Model/effort: Opus, medium | Depends on: 1.4 | Milestone: none

## Goal
Encode snapshots as deltas against the last snapshot acknowledged by each client, keep 64 reference snapshots, fall back to full snapshots when needed, stay within the bandwidth budget and reconstruct the state exactly.

## Crates
- Owns: `server` (snapshot module).
- Read-only: `sim`, `net`, `protocol`, `core`.
- `protocol` is not owned by this lot. If delta codecs must be added to its public interface, stop and report. Preferred: keep the codec as a private module in `server`, unless lot 1.1 already reserved it.
- Forbidden: every other crate.

## Spec
Section 6, snapshots:
- Each snapshot is coded as a delta against the last snapshot acknowledged by this client.
- The server keeps 64 reference snapshots.
- If the acknowledgement refers to a snapshot older than the 64 kept (or unknown), the server sends a full snapshot.
- Per entity: a bitmask of changed fields, then only the changed quantized fields (formats as in lot 1.4).
- Creation and removal of entities must be encoded explicitly (plan does not fix the format: define it and document it).
- Projectiles are not replicated frame by frame: the server sends one creation event (origin, velocity, tick, seed) on channel 2; clients simulate them locally (client part later).
- Acknowledgement carrier: the plan does not say where the client's acknowledgement travels. Decision for this lot: the client's last received snapshot tick is added to each input packet (channel 0). Document this decision.
- Budget: 16 players, about 12 bytes per entity delta, 30 Hz, about 6 kB/s per client. Hard limit: below 100 kbit/s downlink per client at 16 players.

## Public interfaces to create or respect
- Snapshot encoder/decoder pair (delta against a reference), reference ring of 64 snapshots, acknowledgement handling.
- Full snapshot fallback path.

## Acceptance criteria
- Proptest: random world sequences; delta encode then reconstruct equals the full quantized state exactly.
- An acknowledgement older than the 64-snapshot ring triggers a full snapshot (test).
- Measured downlink at 16 players is below 100 kbit/s per client; the measured value is reported (test or benchmark output).
- `docker compose run --rm dev cargo xtask test` passes.

## Out of scope
Client-side prediction and reconciliation (1.6), interpolation (1.7), projectile simulation on clients (later), transport changes.
