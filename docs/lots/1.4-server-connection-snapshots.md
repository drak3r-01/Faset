# Lot 1.4 — server: connection, command buffer, tick loop, full snapshots
- Model/effort: Sonnet, medium | Depends on: 1.2, 1.3 | Milestone: none

## Goal
Make the `server` library accept clients, buffer their commands per tick, run the fixed tick loop and send full snapshots, so two headless clients see each other's positions.

## Crates
- Owns: `server`.
- Read-only: `sim`, `net`, `protocol`, `core`.
- `minigame-api` is a dependency in section 4 but does not exist yet (phase 4): do not depend on it in this lot.
- Forbidden: every other crate.

## Spec
Server API (section 7): `Server::new(config, transports)` accepts several transports at once; `server.tick()` advances one step.

Tick loop: sleep until the next tick, then an active wait of about 1 ms for precision. Under overload, catch-up is limited to 5 ticks per loop iteration.

Connection handshake (section 6):
1. Client sends protocol version and build fingerprint. Mismatch: reject.
2. Server replies with mode, player id, map fingerprint (BLAKE3 hash of the map's canonical form, plan section 13), tick rate.
3. Client loads the map (download is lot 1.x later; here only fingerprint match is required).
4. Client sends `Ready`.
5. Server sends a full snapshot; the client enters the game.

Command buffer (section 6): one per client, commands ordered by tick. If the command for the current tick is missing, repeat the last command. Commands are read at the start of the tick (system order step 1, lot 1.2).

Snapshots (this lot: full snapshots only):
- Sent at 30 Hz by default, configurable 20 to 60 Hz.
- Each entity: position quantized to 1/256 m per axis (24 bits); velocity 1/16 m/s per axis (16 bits); yaw 16 bits; pitch 12 bits; health, weapon and states as compact integers and bits.
- Each snapshot carries the tick of the last command processed for that client.

Bots (section 7): internal virtual clients that produce commands through the same path as humans. Only the hook is needed here.

## Public interfaces to create or respect
- `Server::new(config, transports: Vec<...>)`, `Server::tick()`, client connect and disconnect, `ServerConfig` (snapshot rate, tick rate, limits).
- Read the crate-level types of `sim` and `protocol` without changing them.

## Acceptance criteria
- Integration test, one process, no window: one server, two headless clients. Each client moves; each receives snapshots containing both entities; positions match within 1/256 m (test).
- Measured tick rate is 60 Hz within tolerance (test).
- Version mismatch in handshake is rejected (test).
- `docker compose run --rm dev cargo xtask test` passes.

## Out of scope
Delta snapshots and acknowledgements (1.5), client prediction (1.6), interpolation and lag compensation (1.7), the `dedicated` binary and console (1.8), discovery and integrated hosting (1.9).
