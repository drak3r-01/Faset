# Lot 2.11 — FSR 2/3 through dynamic loading
- Model/effort: Opus, high | Depends on: 2.10 | Milestone: none (highest-risk lot; nothing depends on it)

## Goal
Add FSR 2/3 as an optional upscaler loaded at runtime from AMD's official library, active on Windows x86_64 and cleanly absent elsewhere.

## Crates
- Owns: a feature-gated module inside `upscale`. Adds `libloading` and `bindgen`-generated bindings.
- `unsafe` is allowed in `upscale` only; keep it confined to the FFI module.
- Read-only: `render`, `shaders`, `core`, and the `Upscaler` trait of lot 2.10.
- Forbidden: changing the `Upscaler` trait or `UpscaleInputs`. If FSR 2/3 needs an input that is missing, stop and report.
- Do not compile C++ cross-platform: FFI only, through `libloading` and `bindgen`.

## Spec
- Dynamic loading of the official AMD FSR library with `libloading`. Bindings generated by `bindgen`. Avoids cross-compiling C++.
- Availability matrix: Windows x86_64 yes; Windows ARM64 "to evaluate" (do not enable, report only); Linux x86_64 later phase (not in this lot); Linux ARM64 no; macOS no.
- The official library is not versioned in the repository and no binary is committed. Check its licence before any redistribution step, and record the result in the report.
- Startup detection: library present, loadable, initialises, GPU supported. The menu offers FSR 2/3 only when usable. Any failure falls back to FSR 1 (lot 2.10).
- Quality levels as in lot 2.10: Quality 1.5, Balanced 1.7, Performance 2.0, Ultra Performance 3.0 (per axis).
- Map `UpscaleInputs` to the library call: HDR colour before tonemapping, depth, motion vectors, jitter, exposure, frame time, near and far planes, field of view, reactive mask, reset flag (on respawn and teleport).
- Depth uses the reversed-Z infinite projection of lot 2.2 (`D32_SFLOAT`). Tell the library the matching depth convention. Plan Projection mapping (`n` = near plane):
```
z_{ndc} = \frac{n}{-z_{vue}}
```

## Public interfaces to create or respect
- Respect `upscale::Upscaler` and `UpscaleInputs` from lot 2.10.
- Add a registry entry `Fsr2` / `Fsr3` (report which one is shipped; both are the same library family in this plan).

## Acceptance criteria
- `cargo xtask build --target x86_64-pc-windows-msvc` succeeds in Docker.
- `cargo xtask test` passes on Linux with the library absent: detection returns unavailable and the selection falls back to FSR 1 (unit test).
- Unit test: a mock library reporting failure at init leads to FSR 1 fallback.
- Unit test: `UpscaleInputs` mapping sets the reset flag and the jitter values exactly as given.
- `cargo tree -p dedicated` does not contain `libloading`, `ash` or `winit`.
- `cargo xtask ci` passes in Docker.
- Manual check on the Windows host (not a gate): with the library present, the J2 scene upscales in FSR 2 mode. Report the result.
- `git ls-files` shows no AMD library binary.

## Out of scope
- DLSS (lot 2.12).
- Linux x86_64 FSR 2/3 (later phase), Windows ARM64 evaluation (report only).
- Any change to FSR 1 or to the TAA of lot 2.10.
