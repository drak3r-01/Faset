# Lot 4.1 — `minigame-api`, registry, match phases, witness race mode
- Model/effort: Opus, medium | Depends on: 1.4 | Milestone: none

## Goal
Create the mini-game framework (server and client traits, static registry, match phases, common services) and a minimal witness mode, a race between two zones with no weapons, which must run without any change to `minigame-api`.

## Crates
- Owns: `minigame-api` (new), `mode-race` (new, witness mode).
- Read-only: `sim`, `protocol`, `server`, `core`, `net`.
- Forbidden: `mode-fps`, `bots`, `render`, `ui`, `client` (except nothing: no client wiring in this lot), `editor`, `mapfmt`, `dedicated` (registration is done in the test harness of `server`; if `dedicated` must register it, stop and report).
- Rule: after `mode-race` compiles, `git diff main -- crates/minigame-api` must show no change from the moment it was first merged. Any needed change is an interface defect: stop and report.

## Spec (condensed from plan section 14)
A mode is a crate implementing two traits, one server-side and one client-side, and registered in a registry. Adding a mode touches neither the engine nor the protocol.

Plan section 14, verbatim:
```
pub trait GameMode {
    fn descriptor() -> ModeDescriptor where Self: Sized;
    fn on_match_start(&mut self, ctx: &mut ModeCtx);
    fn on_player_join(&mut self, ctx: &mut ModeCtx, player: PlayerId);
    fn on_player_leave(&mut self, ctx: &mut ModeCtx, player: PlayerId);
    fn on_tick(&mut self, ctx: &mut ModeCtx);
    fn on_event(&mut self, ctx: &mut ModeCtx, event: &GameEvent);
    fn result(&self) -> Option<MatchResult>;
    fn replicated_state(&self) -> Vec<u8>;
}
pub trait GameModeClient {
    fn apply_state(&mut self, bytes: &[u8]);
    fn on_event(&mut self, event: &GameEvent);
    fn draw_hud(&mut self, ui: &mut HudCtx);
}
```
- `ModeDescriptor`: id, display name, compatible map labels, bot support flag, typed settings schema (bounds, defaults). The host menu is generated from this schema.
- `MatchResult` type is defined in this lot. `HudCtx` is a stub here; the `ui` lot fills it.

Mode messages travel in `ModeMessage(mode_id, bytes)`. `protocol` knows no mode.
Registration is static at startup: `registry.register::<RaceMode>()`. No dynamic loading.
Shared simulation systems of a mode live in a module run by both server and prediction.

Services given to modes by `minigame-api` (this lot gives the minimum): spawn and respawn points, teams, score table, timers, event feed, bot control interface (stub). Damage chain, pickups and weapons come later (4.4, 4.7).

Match phases (server is authoritative, end tick replicated):
- `Warmup`: waiting for players, free movement.
- `Countdown`: 3 s.
- `Playing`: until the timer ends or the win condition is met.
- `RoundEnd`: score table, 8 s.
- `MapChange`: next map of the rotation.
- `Loading`, then back to `Warmup`.

Witness mode `mode-race`: two zones (plan: "une course entre deux zones"; kind `Objective` is a decision), A then B in order; the first player to touch B after A wins; the match ends on that result. Movement: basic player motion already available from lots 1.x (decision: if none, fixed-speed horizontal motion from input axes). No weapons, no bonuses.

## Public interfaces to create
- `minigame-api`: `GameMode`, `GameModeClient`, `ModeDescriptor`, `ModeCtx`, `HudCtx` (stub), `GameEvent`, `MatchResult`, `ModeMessage`, `Registry::register::<M>()`, `Phase` enum with the six phases above and their durations as constants.
- `mode-race`: `RaceMode` implementing both traits, descriptor id `race`.

## Acceptance criteria
- `cargo xtask test`: a server test runs a race match with two in-memory clients (transport from `net`) through `Warmup, Countdown (3 s), Playing, RoundEnd (8 s), MapChange, Loading, Warmup`, with the expected winner.
- The phase timings are asserted in simulation ticks, at 60 ticks per second.
- `cargo xtask check` passes.
- `git diff` on `crates/minigame-api` after `mode-race` lands shows no change (interface validated).

## Out of scope
FPS rules, weapons, bonuses, HUD drawing, bots, client state machine (6.1), real map rotation, any `mapfmt` change.
