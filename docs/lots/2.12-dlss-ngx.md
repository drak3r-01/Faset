# Lot 2.12 — DLSS through NVIDIA NGX
- Model/effort: Opus, high | Depends on: 2.10 | Milestone: none (highest-risk lot; nothing depends on it)

## Goal
Add DLSS through the NVIDIA NGX SDK behind the cargo feature `dlss`, active on RTX cards on Windows x86_64 and cleanly absent elsewhere.

## Crates
- Owns: `upscale`, feature `dlss`, its FFI module and build script.
- `unsafe` is allowed in `upscale` only, confined to the FFI module.
- Read-only: `render`, `shaders`, `core`, and the `Upscaler` trait of lot 2.10.
- Forbidden: changing the `Upscaler` trait or `UpscaleInputs`. If DLSS needs a missing input, stop and report.

## Spec
- Option: cargo feature `dlss`. Windows x86_64 only. Not available on Windows ARM64 (not supported), Linux or macOS.
- Binding: FFI to the NGX SDK. Use `bindgen`, as in lot 2.11, unless the SDK requires otherwise (report the choice).
- The NGX SDK is fetched during the build inside Docker. It is never versioned in the repository. The build step must fetch it, not the repo.
- Licence: read the SDK licence in this lot before writing the fetch step. Record a summary of the terms in the PR description. If the licence forbids the planned distribution (the `dist/` folder copied to the host), stop and report.
- Startup detection: NGX initialises, the GPU is an RTX card, the feature is supported. The menu shows DLSS only when usable. Any failure falls back to FSR 1 (lot 2.10).
- Quality levels as in lot 2.10: Quality 1.5, Balanced 1.7, Performance 2.0, Ultra Performance 3.0 (per axis).
- Map `UpscaleInputs`: HDR colour before tonemapping, depth, motion vectors, jitter, exposure, frame time, near and far planes, reactive mask, reset flag (respawn, teleport). Depth uses the reversed-Z infinite projection of lot 2.2, with the plan's Projection mapping (`z_ndc = n / (-z_vue)`):
```
z_{ndc} = \frac{n}{-z_{vue}}
```

## Public interfaces to create or respect
- Respect `upscale::Upscaler` and `UpscaleInputs` from lot 2.10.
- Add a registry entry `Dlss`, present only when the feature is compiled and the GPU is usable.

## Acceptance criteria
- `cargo xtask build --target x86_64-pc-windows-msvc --features dlss` succeeds in Docker, the SDK being fetched by the build.
- `cargo xtask build --target x86_64-unknown-linux-gnu` succeeds without the feature and without the SDK.
- Unit test: unavailable NGX (or non-RTX GPU, simulated) falls back to FSR 1.
- Unit test: `UpscaleInputs` mapping sets the reset flag and the jitter exactly as given.
- `git ls-files` shows no NGX file or SDK binary.
- `cargo xtask ci` passes in Docker.
- Manual check on an RTX host (not a gate): J2 scene in DLSS mode. Report the result.

## Out of scope
- FSR 2/3 (lot 2.11), Linux or macOS DLSS (not planned).
- Settings menu (lot 6.4).
- Any change to lot 2.10 TAA or FSR 1.
