# Lot 5.4 — Editor: continuous validation, immediate test, files
- Model/effort: Sonnet, medium | Depends on: 5.3, 1.9 | Milestone: none

## Goal
Edits are validated live, a map can be tested at once from the editor, and maps are saved, exported, imported and autosaved; a dedicated server loads the exported map.

## Crates
- Owned: `editor`.
- Read-only: `mapfmt` (validator rules, fingerprint, RON I/O), `server`, `dedicated`, `net`, `sim`, `ui`, `render`, `core`.
- Forbidden: changing public interfaces of read-only crates.

## Spec
Validation (runs continuously on each edit; clicking an error moves the camera onto it). Rules from the map format:
- schema and version correct; file at most 256 KB; triangle budget respected;
- each spawn stands on ground, outside any solid, with 2 m of free height;
- enough spawns for the maximum player count, per team;
- accessibility: from each spawn the navigation graph reaches every other spawn and every pickup;
- no spawn in direct line of sight of an enemy spawn within 8 m;
- a `KillVolume` covers everything below the map;
- balance: each team's distances to objectives and major pickups differ by less than 5 %;
- informative only: longest line of sight, playable area, cover density.

Test button: starts an integrated server (lot 1.9 `server`, memory transport) on the current map and spawns the player at the camera position.

Files:
- Save to the user's `maps/` folder in the game data directory, as RON. Format example (section 13):
```
Map(
    format_version: 1,
    meta: (name: "Cargo", modes: ["fps"], players: (2, 12)),
    theme: (ambience: "sunset", palette: "industrial"),
    symmetry: Rotate180,
    brushes: [
        Box(min: (-40, -1, -30), max: (40, 0, 30), material: "concrete"),
        Box(min: (4, 0, -6), max: (10, 3, -3), material: "container_red"),
        Wedge(min: (10, 0, -6), max: (14, 3, -3), rise: PosX, material: "metal"),
    ],
    props: [(recipe: "crate_wood", at: (2.0, 0.0, 5.0), yaw: 15.0)],
    spawns: [(at: (-36.0, 0.0, -26.0), yaw: 45.0, team: A)],
    pickups: [(kind: Health, at: (0.0, 0.5, 0.0), respawn_s: 30)],
)
```
- Export and import (copy a map file in or out).
- Autosave every 60 s to a separate autosave file.
- Map identity: BLAKE3 fingerprint of the canonical form. The plan does not define the canonicalisation; decision, record it in the report.

## Public interfaces to create or respect
- `editor`: `ValidationPanel` (list of issues with location and rule id), `TestSession` launcher, `FileService` (save, export, import, autosave).
- Use `mapfmt` validator functions as they are.

## Acceptance criteria
- `dev.ps1 test` passes:
  - each validator rule has a fixture that fails it with the expected rule id, and the sample map passes;
  - clicking an issue sets the camera target to the issue location (unit test on the camera target);
  - autosave fires after 60 s on a simulated clock and never overwrites the saved file;
  - exported map reloads with the same fingerprint.
- Headless check in Docker: export the test map, place it in the `maps/` folder next to the `dedicated` executable, start `dedicated`, and one simulated client joins and receives a snapshot.
- `dev.ps1 ci` passes.

## Out of scope
- Map catalogue (5.6); bot trials (5.5); changing validator rules (owned by `mapfmt`; stop and report if a rule is wrong).

5. Conventional Commits in English; one lot = one branch = one PR; run the graphify MCP graph refresh (if the MCP exposes one; otherwise say so in the report) once code exists.

Conventions: repo content in English; metres/seconds/radians; right-handed, Y up, -Z forward; data RON; `thiserror` in libraries, `anyhow` in executables, `tracing` for logs; never change a crate's public interface you do not own.
