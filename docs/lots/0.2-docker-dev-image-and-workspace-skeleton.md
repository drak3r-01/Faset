# Lot 0.2 — Dev Docker image, host scripts, workspace skeleton, `xtask` check/test
- Model/effort: Sonnet, medium | Depends on: 0.1 | Milestone: none

## Goal
Make `cargo xtask ci` pass on an empty workspace, entirely inside Docker, driven from the Windows host by thin scripts.

## Crates
- Owned: `xtask` (new), root `Cargo.toml` (workspace), `rust-toolchain.toml`, `Dockerfile` and `docker-compose.yml`, `dev.ps1`, `dev.sh`.
- Forbidden: none exists yet; do not create any other crate (owning lots create theirs).
- Read-only: `CLAUDE.md`, `docs/plan.md`.

## Spec (condensed)
Host requirements: Docker Desktop with WSL2 engine, and Git. Nothing else is installed on the host.

Image `dev` contents:
- Rust stable pinned in `rust-toolchain.toml`.
- `clang`, `lld`, `cargo-xwin`, `cargo-nextest`, `cargo-deny`, `sccache`.
- Mesa lavapipe (software Vulkan) and Vulkan validation layers.
- The image config accepts the Microsoft SDK licence needed by `cargo-xwin`.
Purpose: compile, test, headless rendering.

Image `server-runtime` is NOT built here (lot 0.4).

Scripts: `dev.ps1` and `dev.sh` only run `docker compose run --rm dev cargo xtask <command>`. All logic lives in `xtask`, in Rust.

Volumes and performance:
- `target/` and the Cargo registry are named Docker volumes, never bind-mounted from the Windows disk.
- The repo is bind-mounted from the host.
- `sccache` cache lives in a named volume shared across sessions.

`xtask` commands to implement now:
- `check`: `fmt --check` then `clippy -D warnings` (plan section 3 command table). Cargo flags such as `--workspace --all-targets` are a lot decision, not in the plan.
- `test`: unit and integration tests run with `nextest` (plan section 3). `--workspace` is a lot decision.
- `render-test`, `maps validate`, `deny` (`cargo deny check`): may be stubs that succeed with zero items, but must exist and be wired.
- `ci`: runs in order `check`, `test`, `render-test`, `maps validate`, `deny`; stops at the first failure.
- `build --target <t>`, `package`, `run-server`: out of scope here (0.3 and later).

Workspace: root `Cargo.toml` with `[workspace] members = ["xtask"]` and `[workspace.package] version = "0.0.0"` (the release tag check in 0.4 compares against this). Add `resolver = "2"`. `xtask` has `#![forbid(unsafe_code)]`, uses `anyhow`.

## Public interfaces to create or respect
- Command-line surface of `xtask`: `cargo xtask <check|test|render-test|maps validate|deny|ci>`.
- `dev.ps1 <command>` and `dev.sh <command>` forward arguments unchanged.

## Acceptance criteria
- `docker compose build dev` succeeds.
- `.\dev.ps1 ci` (or `./dev.sh ci`) exits 0 on the empty workspace.
- `docker compose run --rm dev cargo xtask check` and `... test` each exit 0 individually.
- `docker compose run --rm dev cargo deny --version` and `cargo nextest --version` print versions (tools present).
- `docker compose run --rm dev vulkaninfo --summary` or `ls /usr/share/vulkan/icd.d` shows lavapipe present.
- `target/` and registry paths resolve to named volumes (`docker volume ls` shows them after a build).

## Out of scope
- Cross-compilation targets and the lavapipe render tests (0.3).
- Any crate other than `xtask`.
- The `server-runtime` image and the GitHub workflow (0.4).
- Game code of any kind.
