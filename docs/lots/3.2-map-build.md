# Lot 3.2 — Map build: meshes, collisions, per-vertex occlusion
- Model/effort: Sonnet, medium | Depends on: 3.1, 2.3, 1.2 | Milestone: none (plan: junction of the three parallel streams)

## Goal
Turn a `MapFile` (after expansion) into CPU meshes and a collision world, bake per-vertex ambient occlusion, so that the example map renders and can be walked on.

## Crates
- Owns: `mapfmt` (new module `geometry`), `sim` (new module `map_collision`), and the map-loading wiring in `client` (new module only).
- Read-only: `core`, `assets`, `render`, `protocol`.
- Forbidden: `minigame-api`, `mode-*`, `bots`, `net`, `server`, `dedicated`, `upscale`, `ui`, `editor`, `tools/map-tool`, and any public interface of `mapfmt` already published in 3.1 (add, do not change).
- Decision (not fixed by plan): `mapfmt` must not depend on `sim`, so the mesh builder lives in `mapfmt` (pure CPU data), and the collision build lives in `sim`, which already depends on `mapfmt`. The AO baker takes a callback, so `mapfmt` stays free of `sim`.

## Spec (condensed from plan sections 13, 5, 8)
Load pipeline, numbered as in the plan. This lot implements steps 1 to 3 only.
1. Read, migrate, apply symmetry and prefabs (lot 3.1).
2. Meshes (this lot).
3. Collisions (this lot).
4. Navigation graph (lot 4.9, not here).
5. Height map for weather (later).
The dedicated server runs steps 1, 3 and 4 only: its build must not pull render types.

Meshes:
- Vertex, 20 bytes: position `[f32; 3]` (12 B), normal `[i8; 4]` normalised (4 B), colour and material `[u8; 4]` = RGB + material id (4 B).
- Flat shading: vertices are duplicated per face.
- Hidden faces between touching solid volumes are removed.
- Geometry is grouped in blocks of 16 m (block index = floor(position / 16 m)). One chunk per block.
- Per-vertex ambient occlusion is computed at load with short rays. It is multiplied into the RGB values (no spare byte in the vertex).
- Stairs produce visible steps in the mesh.

Collisions:
- Static map = convex volumes (boxes, ramps, cylinders, prisms) in a bounding-volume tree with `parry3d` (plan section 5). `Stairs` yields one ramp volume.
- One convex volume per brush. Prop collision is declared by its recipe: none, box, convex hull or assembly (plan section 12). Decision: until lot 2.13 supplies recipes, each prop uses its bounding box.
- Queries required: ray cast, shape sweep (capsule), overlap test.
- Player capsule: radius 0.35 m, height 1.8 m (crouch 1.0 m, used by later lots).

## Public interfaces to create
- `mapfmt::geometry::Vertex` (`#[repr(C)]`, 20 bytes, asserted by a test), `pub struct MeshChunk { block: [i32; 3], vertices: Vec<Vertex>, indices: Vec<u32> }`.
- `pub fn build_meshes(map: &MapFile) -> Vec<MeshChunk>`.
- `pub fn bake_occlusion(chunks: &mut [MeshChunk], occluded: impl Fn(Vec3, Vec3, f32) -> bool)`.
- `sim::map_collision::MapCollision`: `build(map: &MapFile) -> Self`, `ray_cast(origin, dir, max_dist) -> Option<f32>`, `sweep_capsule(...)`, `overlaps_capsule(...)`. Exact signatures are chosen here and then respected by lots 4.2 and 4.9.

## Acceptance criteria
- `cargo xtask test`: `size_of::<Vertex>() == 20`; a shared face between two touching boxes produces no triangles; a 16 m block boundary splits chunks; AO values lie in [0.0, 1.0].
- Walkability test in `sim`: a capsule placed on the example map spawn stays on the floor (ray down hits floor within 0.05 m), and a sweep toward a wall stops before it.
- `cargo xtask render-test`: the example map renders on lavapipe and matches its reference image (reference image created in this lot).
- `cargo xtask check` passes.

## Out of scope
Movement controller (4.2), navigation graph (4.9), height map (later), map validation (3.3), mesh-level material work (lot 2.x), upload to GPU arena beyond what the client wiring needs.
