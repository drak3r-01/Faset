# Lot 2.13 — `assets`: mesh recipes, palettes, validator, thumbnails
- Model/effort: Sonnet, medium | Depends on: 2.3 | Milestone: none

## Goal
Turn RON prop recipes into triangle meshes, with palettes, a validator (`asset-tool validate`) and offscreen thumbnails, so that every prop is data and no model file is ever imported.

## Crates
- Owns: `assets` (depends on `core` only) and a new binary `tools/asset-tool` (depends on `assets` and `render`). `asset-tool` is not in the plan's crate table: create it, and report it as a deviation.
- Read-only: `render` (thumbnail rendering through its public API), `core`.
- Forbidden: changing the public interface of `render` or `core`.
- Errors: `thiserror` in `assets`, `anyhow` in `asset-tool`. Logs: `tracing`. Units: metres. Y up, -Z forward.

## Spec
- No imported model file. Every object is a RON recipe turned into a mesh at load time.
- Primitives: box, ramp, cylinder with n sides, cone, sphere at low subdivision, prism, torus, polygon extrusion, profile revolution.
- Operations: transform, mirror, repeat, merge, flat normals, per-vertex colours.
- Recipe fields: primitives and operations; colours as palette names only (`wood`, `metal`, `accent1`, ...), resolved from the map theme palette at use; optional `seed` for variants (tree height, rock shape); declared collision: `none`, `box`, `convex hull` or `compound`.
- Recipe example (plan section 12, verbatim):
```
Prop(
    id: "crate_wood",
    tags: ["cover", "urban"],
    collision: Box,
    parts: [
        Box(size: (1.0, 1.0, 1.0), color: "wood", pattern: Planks),
        Repeat(count: 4, rotate_y: 90.0, part:
            Box(size: (0.08, 1.02, 0.08), at: (0.5, 0.0, 0.5), color: "wood_dark")),
    ],
)
```
- Deterministic: same recipe and seed give the same mesh.
- Vertex format: 20 bytes. Position 3 x f32; normal 4 x i8 normalised; colour and material id 4 x u8. Shading is flat: vertices duplicated per face. Weapons may declare smoothing groups.
- Triangle budgets: prop 20 to 200; character about 300; weapon 200 to 600; full map under 150 000.
- `asset-tool validate <path>`: checks syntax, budget and dimensions of each recipe, renders a thumbnail without a window (lavapipe in Docker), and writes a contact sheet (planche) of thumbnails for visual review.
- Reference set: ten props validated. Suggested location `assets/props/reference/` (report the path chosen).

## Public interfaces to create or respect
- `assets::Recipe` (serde from RON), `assets::build_mesh(recipe, palette, seed) -> Mesh`, `assets::Palette`, `assets::Validation` report type.
- `asset-tool validate <dir>` CLI; exit code non-zero on any error.

## Acceptance criteria
- Unit tests: each primitive's vertex and triangle counts match its parameters; flat normals are unit length; the same seed gives an identical mesh.
- Property test (`proptest`): recipe RON round-trip is stable.
- `asset-tool validate assets/props/reference` passes on the ten reference props, each within its budget.
- `cargo xtask render-test`: thumbnails match references within tolerance; zero validation-layer messages on lavapipe.
- `cargo xtask build --target x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu` succeed.
- `cargo xtask ci` passes in Docker.

## Out of scope
- Prop library (lot 2.14), characters and weapons (lot 2.15), maps (phase 3), any imported model or texture.
- Audio recipes (lot 2.17).
