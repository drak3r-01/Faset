# Lot 4.4 — Hitscan weapons, spread, recoil, damage chain, respawn
- Model/effort: Sonnet, high | Depends on: 4.2, 1.7 | Milestone: none

## Goal
Implement the shared shot pipeline for hitscan weapons (predicted by the client, validated by the server) with deterministic spread, recoil, damage chain and respawn.

## Crates
- Owned: `mode-fps` (weapon model, shot pipeline, damage chain, respawn choice).
- Read-only: `sim` (character, collisions, map raycast), `minigame-api` (`GameMode`, services), `protocol`, `server` and `net` (only their existing public API, including the lag-compensation history from lot 1.7), `core` (typed ids, time, maths).
- Forbidden: changing the public interface of `sim`, `minigame-api`, `server`, `net`, `protocol`, `core`. If a hook is missing, stop and report.

## Spec
### Weapon data (RON, one file per weapon)
Fields: type `Hitscan | Projectile | Melee | Beam`; fire mode `Auto | Semi | Burst`; rpm; pellets per shot; base damage D0, head multiplier, falloff start r0, falloff end r1, floor multiplier m_min; magazine, reserve, reload time, draw time (exit time); spread: sigma_base, sigma_max, delta_beta per shot, return time constant tau, multipliers for movement and airborne; recoil: per-shot pattern, random-part fraction, return stiffness omega; sight: field of view, spread multiplier, speed multiplier; optional projectile block (lot 4.5).

### Fire cadence
Time is kept in seconds, never rounded to ticks: t_next <- t_next + 60/rpm. A shot is allowed when t_now >= t_next. The server recomputes fire rate, ammo and spread, and rejects shots that break cadence.

### Spread
Each shot draws u1, u2 uniform from a PCG generator seeded with (server seed, player id, shot counter). With camera basis F (forward), R (right), U (up):
r = tan(sigma) * sqrt(u1); phi = 2*pi*u2; d = normalize(F + r*cos(phi)*R + r*sin(phi)*U).
Current cone: sigma = min(sigma_base * m_state + beta, sigma_max), where m_state combines movement, airborne and sight multipliers.
Per shot: beta <- beta + delta_beta. Per tick: beta <- beta * exp(-dt/tau).
Client and server must obtain the same direction bit for bit.

### Recoil
Each shot adds a view offset read from the weapon pattern (fixed part plus random fraction). The offset returns to zero with a critically damped spring: x'' = -omega^2 (x - x_target) - 2*omega*x', x_target = 0. The client predicts it, the server recomputes it.

### Hitscan
- Ray from the shooter's eye (origin o, unit direction d). The map raycast gives the stop distance d_stop.
- Server: test the ray against player hitboxes rewound to the shot instant (lag compensation, lot 1.7). Body = capsule (radius 0.35 m, height 1.8 m, 1.0 m while sliding); head = sphere. Head tested before body. The earliest contact with distance < d_stop wins.
- Ray-sphere (centre c, radius r): m = o - c; b = m.d; q = |m|^2 - r^2; if b^2 >= q then t = -b - sqrt(b^2 - q).
- Falloff: D(r) = D0 * mix(1, m_min, clamp((r - r0)/(r1 - r0), 0, 1)), mix(a,b,t) = a + (b - a) t. Head hits multiply by the head multiplier.
- Shotguns: each pellet has its own direction (own PCG draws); damage is summed per victim.

### Damage chain
`DamageEvent` = attacker, victim, amount, type, zone (head/body), position. Modifiers in order: armour (absorbs first), class, active bonuses (lot 4.7), friendly fire off in team modes, spawn protection 1.5 s (no damage). Health decreases; at 0: death, score, kill-feed event, respawn after 3 s.

### Respawn
Candidate spawn points: maximise distance to the nearest enemy; exclude points visible from any enemy. Pick uniformly at random among the best three, using the deterministic PCG.

## Public interfaces to create or respect
- `mode-fps`: `WeaponDef` (serde, RON), `WeaponState`, a pure shot function shared by client prediction and server validation taking time, seed and counter explicitly (no globals), `DamageEvent`, a pure respawn choice function.
- Implements `minigame-api::GameMode` unchanged. Messages travel as `ModeMessage(mode_id, bytes)`; `protocol` knows no mode.
- Exact signatures are chosen by the session; document them in the crate.

## Acceptance criteria
- `cargo xtask test` passes unit tests: ray-sphere hit, miss and tangent; falloff at r0, r1 and beyond; head before body; first contact before stop distance.
- `spread_identical_client_server`: same seed and counter give a bitwise identical direction on both paths.
- A shot at a moving target with 100 ms simulated latency hits.
- Cadence: 600 rpm gives 0.1 s spacing; the server rejects a shot sent 0.05 s after the previous one.
- Spawn protection blocks damage for 1.5 s; respawn happens at 3 s; spawn choice never picks a point visible from an enemy.
- `cargo xtask ci` is green.
