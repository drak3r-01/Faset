# Lot 6.11 - Props and vegetation (internal lot)

Not in the reference plan. The client does not render map `props` at all yet, and the scenery has no vegetation.

- **Model/effort:** Opus, high | **Depends on:** 6.10 | **Branch:** `lot/6.11-props-vegetation` (one PR)
- **Owns:** `client` (prop rendering), `assets` (generators), `render` (instancing). **Additive changes allowed in:** `mapfmt` (vegetation placement data), `editor` (placement/paint brush), `docs`.

## Goal

Maps look alive: props are drawn and dense vegetation costs almost nothing.

## Spec

1. **Render map props** from the existing prop catalogue (finally drawn by the client).
2. **Code-generated low-poly vegetation** (no external assets): tree species, rocks, bushes, palms, grass tufts, ferns; pixel-art palette of our own, variants per theme.
3. **GPU instancing** for very dense vegetation (thousands of instances; GPU or chunked CPU culling is a decision), wind sway for grass/leaves in the shader, LODs and distance fade, terrain-aware placement (on the 6.10 height).
4. **Placement:** density rules per material in the map file plus hand-placed props; deterministic from a seed.
5. **Gameplay:** vegetation blocks sight (bot line of sight and AI) but not bullets; no collision for grass; trunks/rocks may get simple colliders (decision).
6. **Budgets:** stay inside the frame budgets of the existing perf tests; add a vegetation-heavy render benchmark.

## Acceptance

`cargo xtask ci` green; lavapipe render tests of each species and of a dense field; instancing unit tests; bot LOS test through vegetation.
