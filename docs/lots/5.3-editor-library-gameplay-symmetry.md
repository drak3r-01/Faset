# Lot 5.3 — Editor: library, gameplay, ambiance, symmetry
- Model/effort: Sonnet, medium | Depends on: 5.2 | Milestone: none

## Goal
A complete map (props, gameplay points, ambiance, symmetry) can be created in the editor without touching the file by hand.

## Crates
- Owned: `editor`.
- Read-only: `mapfmt`, `assets` (prop recipes, palettes, thumbnails), `render`, `ui`, `sim`, `core`.
- Forbidden: changing public interfaces of read-only crates.

## Spec
- Library: props shown with thumbnails (rendered headless from recipes), materials, palettes, prefabs (group of volumes and props placed repeatedly; a building described once).
- Gameplay tools:
  - spawns: point with orientation and team;
  - pickups: location, type, respawn delay;
  - zones: `KillVolume`, `Water`, `JumpPad`, `Teleporter`, `LowGravity`, `Objective`;
  - lights: point lights.
- Meta and theme panels: name, author, description, compatible modes, recommended player count; sky, weather calendar, ambiance profile, colour palette. Changes show an immediate preview.
- Physics block: local overrides of gravity and speed.
- Symmetry toggle: `None`, `MirrorX`, `MirrorZ`, `Rotate180`. When enabled, every command also applies its mirror image, so the author describes one half and balance is guaranteed. Mirror planes: X = 0 for `MirrorX`, Z = 0 for `MirrorZ`, both for `Rotate180` (point reflection through the origin: (x, y, z) to (-x, y, -z)). Decision: the plan does not fix the pivot, so the origin is used; record it in the report.
- Prefabs are written once and instanced; `Stairs` produce visible steps and a collision ramp.

## Public interfaces to create or respect
- `editor`: library panel, tool enum (brush, prop, spawn, pickup, zone, light), `Symmetry` mode applied inside `Command` execution.
- Respect `mapfmt` block types exactly.

## Acceptance criteria
- `dev.ps1 test` passes:
  - a full map (brushes, prefab instance, 2 spawns per team, pickups, a `KillVolume` below the map, a sky) is created through the editor API only, saved, and reloaded identical;
  - with `MirrorX` on, a brush placed at x > 0 has a mirrored twin at x < 0; `Rotate180` mirrors both axes; undo removes both twins in one step;
  - prefab instances reference one definition.
- `dev.ps1 maps validate` passes for the test map (only structural errors counted here; full rules are lot 5.4).
- `dev.ps1 ci` passes.

## Out of scope
- Validation panel and test launch (5.4); map catalogue (5.6); AI map generation.

## Session protocol
1. Read `CLAUDE.md` and this file.
2. Do not use graphify until the repo contains Rust code; then query it (`graphify query`, `path`, `explain`) before grepping.
3. Branch `lot/5.3-editor-library-gameplay-symmetry`. All commands run in Docker (`dev.ps1 <cmd>`), never on the host.
4. Run `dev.ps1 ci` (= `cargo xtask ci`) before merge; it is the only quality gate.
5. Conventional Commits in English; one lot = one branch = one PR; run `graphify update .` once code exists.
6. Short report: delivered, tests passed, deviations from this file.

Conventions: repo content in English; metres/seconds/radians; right-handed, Y up, -Z forward; data RON; `thiserror` in libraries, `anyhow` in executables, `tracing` for logs; never change a crate's public interface you do not own.
