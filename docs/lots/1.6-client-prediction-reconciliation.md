# Lot 1.6 — Client clock sync, prediction, reconciliation, smoothing
- Model/effort: Opus, high | Depends on: 1.5 | Milestone: none

## Goal
Make the client predict its own movement, reconcile against server snapshots using a 128-tick history, keep its clock within 5 % of real speed, and smooth corrections so the display never teleports. Prediction error mean must stay below 5 cm under degraded network conditions.

## Crates
- Owns: `client` (create the crate if absent, with dependencies as in section 4; this lot owns its clock and prediction modules).
- Read-only: `sim`, `net`, `protocol`, `server` (dev-dependency for integration tests only), `core`.
- No renderer dependency in this lot.
- Forbidden: every other crate, including changes to the public interface of `server`, `sim` or `net`.

## Spec
Clock synchronization (section 6):
- Measure round-trip time with timestamped exchanges; smooth it with the plan's filter (s = new sample):
```
\mathrm{rtt} \leftarrow 0{,}9\,\mathrm{rtt} + 0{,}1\,s \qquad j \leftarrow 0{,}9\,j + 0{,}1\,|s - \mathrm{rtt}|
```
- The client simulates ahead of the server so its commands arrive just before the tick that consumes them:
```
T_{client} = T_{serveur} + \left\lceil \frac{\mathrm{rtt}/2 + 2j}{\Delta t} \right\rceil + m \qquad m \in \{1, 2\}
```
- The server returns the real lead of the client's commands. The client corrects by modulating its simulation speed by at most 5 %, never skipping a tick:
```
\mathrm{timescale} = 1 + \mathrm{clamp}\big(k\,(a_{cible} - a_{mesur\acute{e}e}),\,-0{,}05,\,0{,}05\big)
```
  The plan gives no gain `k` and no explicit definition of the target lead `a_cible` or measured lead `a_mesurée`: lot decision, document the values chosen.
- The server's per-client buffer orders commands by tick and repeats the last command when one is missing (lot 1.4). Each input packet repeats the last 3 unacknowledged commands.

Prediction and reconciliation:
- Circular buffer of the last 128 ticks, each holding the command and the predicted state.
- When a snapshot acknowledges the command of tick k, compare the server state with the predicted state of tick k.
- If the error exceeds tolerance (1 cm position, 5 cm/s velocity), replace the state of tick k with the server state, then replay commands k+1 to the current tick with the same simulation code.
- Do not teleport the display. Keep the visual offset `e` and decay it per tick:
```
e \leftarrow e \cdot e^{-\Delta t/\tau} \qquad \tau = 0{,}1\ \mathrm{s} \qquad \text{recalage imm\'ediat si } |e| > 2\ \mathrm{m}
```
  Snap immediately (no decay) when `|e| > 2 m`.
- Predicted: movement, weapon switching, firing (sound, recoil, tracer), ammunition.
- Never predicted: damage, deaths, bonus pickups.

Targets measured in tests (section 20): prediction mean error below 5 cm under degraded conditions; no lasting state divergence between client and server.

## Public interfaces to create or respect
- Clock sync state (RTT estimate, lead, speed factor in [0.95, 1.05]).
- Prediction history (128 entries), `reconcile(snapshot)`, visual offset with smooth decay.

## Acceptance criteria
- Integration test, headless client and server through the conditioned transport: 100 ms latency, 20 ms jitter, 5 % loss. Mean position prediction error below 5 cm (test).
- Speed factor never leaves [0.95, 1.05]; no tick is skipped (test).
- After a forced correction, the display offset decays and no per-frame jump appears (test with recorded offsets).
- After a quiet period, client state equals server state within the tolerance (test).
- `docker compose run --rm dev cargo xtask test` passes.

## Out of scope
Remote entity interpolation (1.7), lag compensation (1.7), rendering, input devices, UI.
