# Lot 1.1 — core and protocol: types, bit writing, quantization, messages
- Model/effort: Sonnet, medium | Depends on: 0.2 | Milestone: none

## Goal
Provide typed identifiers, time and maths base types in `core`, and a bit-exact wire format (bit writer/reader, quantizers, message enum with versioning) in `protocol`, verified by round-trip property tests.

## Crates
- Owns: `core`, `protocol` (skeletons created by lot 0.2).
- Read-only: `core` is a dependency of `protocol`. External: `glam`, `thiserror`, `tracing`, `proptest` (dev).
- Forbidden: every other crate (`sim`, `net`, `server`, `client`, `render`, ...).

## Spec
Conventions: everything in English; metres, seconds, radians; right-handed, Y up, -Z forward; `#![forbid(unsafe_code)]`; `thiserror` for errors in this library.
`core` (section 4): typed identifiers, time, maths (`glam`), configuration, logging. Simulation step `DT = 1/60 s`.
`protocol` (section 4): messages, bit-level writing, quantization, versions.
Limits: one packet payload at most 1200 bytes. Every decoder returns `Result` with bounded lengths. Never panic on input.
Identifiers: `NetId` is a `u16` assigned by the server, distinct from ECS entity ids. Tick is a `u32`.

Quantization (per field):
| Field | Encoding |
|---|---|
| Position | 1/256 m per axis, 24 bits per axis (signed; range derived from step and width: [-32768, 32767.996] m; plan gives no range) |
| Velocity | 1/16 m/s per axis, 16 bits per axis (signed; range derived: [-2048, 2047.9375] m/s; plan gives no range) |
| Yaw | 16 bits, step 2π/65536 |
| Pitch (snapshot) | 12 bits (plan gives no range; use [-π/2, π/2], document the step) |
| Pitch (command) | i16, same step 2π/65536 as yaw (plan gives no step; document the choice) |
| Health, weapon, states | compact integers and bit flags |

Input command (client to server, channel 0), sent at 60 Hz, fixed field list:
- tick `u32` (4 B), buttons `u16` bitfield (2 B), move axes two `i8` (2 B), yaw `u16` (2 B), pitch `i16` (2 B), weapon slot `u8` (1 B). Total 13 bytes.
- Deviation to report: the plan says "about 10 bytes", but the listed fields sum to 13 bytes. Use the field list.
- Redundancy (last 3 unacknowledged commands per packet) is handled in lot 1.3/1.6, not here.

Messages to define (names are suggestions; keep them stable once added):
- `ClientHello`: protocol version, build fingerprint.
- `ServerHello`: mode, player id, map fingerprint, tick rate.
- `Ready`.
- Snapshot types: full and delta layouts are implemented in lots 1.4 and 1.5; this lot only reserves the message variants and the field codecs.
- Event messages (channel 2): deaths, score, phases, map change, chat.
- Map transfer chunk (channel 3).
- `PROTOCOL_VERSION` constant; a mismatch is rejected at handshake.

## Public interfaces to create or respect
- `core`: `NetId(u16)`, `Tick(u32)`, `DT` constant (1/60 s).
- `protocol`: bit writer and reader (`write_bits(value, n)`, `read_bits(n) -> Result`); quantize/dequantize functions for each field above; `Message` enum with `encode` and `decode -> Result<_, DecodeError>` (thiserror).

## Acceptance criteria
- `docker compose run --rm dev cargo xtask test`: proptest round trip gives identical values for every message variant and every field codec.
- Quantized values reconstruct within half a step (position error <= 1/512 m).
- Decoding arbitrary bytes (proptest) returns `Ok` or `Err`, never panics.
- An encoded input command is exactly 13 bytes (test).
- `docker compose run --rm dev cargo xtask check` is clean.

## Out of scope
Delta encoding (1.5), channels and transports (1.3), sockets, ECS, simulation logic, map format.
