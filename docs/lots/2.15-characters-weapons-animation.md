# Lot 2.15 — Characters, weapons, procedural animation, first-person viewmodel
- Model/effort: Sonnet, medium | Depends on: 2.13 | Milestone: none

## Goal
Build rigid-block player characters and weapon meshes, animate them procedurally from speed, and animate the first-person weapon with critically damped springs (sway, step, recoil).

## Crates
- Owns: character and weapon recipes, generation through `assets`, and the animation math as pure functions in `assets` (no GPU, deterministic).
- Read-only: `render` (viewmodel drawn through the existing pass 8 API), `core`.
- Forbidden: `sim`, `render` public interface. If `render` has no viewmodel API, stop and report.
- Errors: `thiserror`. Units: metres, seconds, radians.

## Spec
- Characters: rigid blocks, no mesh deformation. Budget about 300 triangles.
- Running, jumping and sliding are animated by sinusoidal rotations of limbs. Amplitude and phase follow the horizontal speed. Exact constants go in the recipe and are reported.
- Weapons: budget 200 to 600 triangles. Flat shading; smoothing groups allowed.
- Viewmodel springs: critically damped spring towards a target (plan section 12, verbatim). Use a fixed time step for determinism.
```
\ddot{x} = -\omega^2 (x - x_{cible}) - 2\omega\,\dot{x}
```
- Three viewmodel offsets: sway (balancing), step (pas), recoil (recul).
- Recoil: each shot adds an offset read from the weapon's recoil pattern (plan weapon table, "Recul": per-shot pattern, random part, return stiffness). The offset returns to zero through the same spring (plan section 16: "ressort amorti critique de la section 12"). The client predicts it; the server recomputes it (server work is not in this lot; keep the function pure so both can call it).
- Weapon recoil fields are defined by the weapon data of phase 4. For this lot use a local test recipe.

## Public interfaces to create or respect
- `assets::anim::Spring` (position, velocity, `step(dt, target)`), `assets::anim::limb_pose(speed, phase) -> Pose`, `assets::viewmodel::Viewmodel::on_shot(pattern)`, `Viewmodel::update(dt, inputs) -> Transform`.

## Acceptance criteria
- Unit test: a spring converges to its target within 1e-3 after 1 s at the fixed step used.
- Unit test: after one recoil kick the offset is positive and returns below 1e-3 within the documented time.
- Unit test: limb pose at speed 0 is neutral; pose amplitude grows with speed.
- `cargo xtask render-test`: three frames of a running character at different phases show distinct limb poses; a weapon frame after a shot shows the recoil offset; references match within tolerance; zero validation messages.
- Triangle budgets verified by `asset-tool validate`.
- `cargo xtask ci` passes in Docker.

## Out of scope
- Ballistics, damage, fire rate, dispersion (phase 4).
- Camera eye height, slide transition, landing dip (camera, phase 4).
- Network synchronisation of animations.
- Character classes and loadout (phase 6).
