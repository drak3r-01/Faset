# Lot 1.9 — Integrated server, LAN opening and discovery
- Model/effort: Sonnet, medium | Depends on: 1.4 | Milestone: none

## Goal
Let the client host a game in-process (server on a dedicated thread, memory transport), optionally open it to the LAN on UDP 7777, and let other clients discover it through UDP broadcast on 7778 and join.

## Crates
- Owns: `client` (hosting and server-browser modules).
- Read-only: `server`, `net`, `protocol`, `core`.
- Public interfaces of `net` and `server` must not change. If opening to the LAN needs a change there, stop and report.
- Forbidden: every other crate.

## Spec
Integrated server (section 7):
- The client starts `server` on a dedicated thread, connected by the memory transport.
- The host is an ordinary client: no special case in game code, latency zero.
- A solo game with bots is an integrated server that is not opened to the network.

Opening to the LAN:
- Adds a UDP transport on the game port (default 7777) to the server already running. The server is not restarted.

Discovery:
- The client sends a UDP request to port 7778 on each network interface (broadcast).
- Servers reply with: name, mode, map, players present, maximum players, game port.
- The list refreshes every 2 s. An entry expires after 6 s without a reply.
- The Windows firewall prompt on first run is expected. Do not try to automate it.

## Public interfaces to create or respect
- `host_game(config, open_to_lan: bool)` or equivalent returning a handle to stop the server.
- Server browser: list of discovered entries with the fields above, refreshed and expired as specified.

## Acceptance criteria
- Test: host client opens the game; a second client finds it in the list within 2 s and joins.
- Test: solo game with bots binds no UDP socket (asserted).
- Test: an entry disappears 6 s after the server stops.
- If broadcast is not routable inside the container, test discovery with the broadcast address injected, and report it as a deviation.
- `docker compose run --rm dev cargo xtask test` passes.

## Out of scope
Server-side configuration files (1.8), menus and UI screens (lot 6.x), internet discovery or master server (explicitly out of scope), NAT traversal.
