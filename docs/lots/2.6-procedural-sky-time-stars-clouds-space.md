# Lot 2.6 — Procedural sky: time of day, stars, clouds, space
- Model/effort: Sonnet, high | Depends on: 2.3 | Milestone: none

## Goal
Render a fully procedural sky driven by map time, latitude and cloud settings, whose colours also light the scene; four time-of-day references and the space profile must match.

## Crates
- Owned: `render` (sky pass, sun computation); WGSL in `shaders`.
- Read-only: `core` (time types). Forbidden: all other crates.

## Spec (condensed)
- Sky = one full-screen triangle; colour depends on view direction v. Drawn in pass 3, where depth is empty.
- Sky colour as a function of view direction v (plan form; C_horizon, C_zenith and exponent k are profile values):
```
C_{ciel}(v) = \mathrm{mix}\big(C_{horizon},\ C_{z\acute{e}nith},\ \max(v_y, 0)^{k}\big)
```
- Sun halo: Henyey-Greenstein phase with g = 0.76, θ the angle to the sun (plan form):
```
P(\theta) = \frac{1 - g^2}{4\pi\,(1 + g^2 - 2g\cos\theta)^{3/2}}
```
- Sun position from time: hour angle h = 2π(t/24 − 0.5), t in hours; latitude φ, declination δ, altitude el, azimuth az (plan form):
```
\sin(\mathrm{el}) = \sin\varphi \sin\delta + \cos\varphi \cos\delta \cos h \qquad \mathrm{az} = \mathrm{atan2}\big(\sin h,\ \cos h \sin\varphi - \tan\delta \cos\varphi\big)
```
- Declination δ: the plan's formula uses it, but the plan's per-map config list (section 10) does not include it. Decision: per-map value, default δ = 0 if unset (addition, to record).
- Convert (altitude, azimuth) to a world unit vector: Y up, azimuth measured from −Z clockwise toward +X.
- Stars: direction hashed on a grid, a fraction of cells get a star, slight twinkle over time. Moon as a disc.
- Space profile: nebula from fractal noise; planets as shaded discs.
- Clouds: one layer of fractal noise scrolling with the wind vector, thresholded by cloud cover (0 = clear, 1 = overcast).
- Lighting colours read from the sky: the ambient sky colour of lot 2.4 is sampled from this sky in the upward direction.
- Map config fields (consumed here): time of day, time speed, latitude, cloud cover, wind, star density, profile name.
- Server is authority on time (networked sync is a later lot; here only the value is an input).

## Public interfaces to create or respect
- `pub struct SkyParams { pub time_h: f32, pub time_speed: f32, pub latitude_deg: f32, pub declination_deg: f32, pub cloud_cover: f32, pub wind: Vec2, pub star_density: f32 }` (serde).
- `pub fn sun_direction(time_h: f32, latitude_deg: f32, declination_deg: f32) -> Vec3`.
- `RenderWorld` gains `sky: SkyParams`; sun direction feeds lot 2.5 cascades.

## Acceptance criteria
- `cargo xtask render-test`: four reference images at 06:00, 12:00, 18:00, 00:00 (`sky_06.png`, `sky_12.png`, `sky_18.png`, `sky_00.png`) and `profile_space.png` match within tolerance 1 per channel.
- Unit: `sun_direction` at latitude 0, declination 0, time 12 h points straight up (altitude 90 degrees within 1e-4).
- Unit: at 06:00 and 18:00 the sun altitude is 0 within 1e-3 at equator.
- Unit: HG phase integrates to 1 over the sphere within 1e-3.
- Unit: star hash is deterministic for the same direction.
- Zero validation-layer messages.

## Out of scope
Weather particles and rain (2.7), lightning, sun shadows (2.5 uses this sun), moon phases, orbital motion of planets beyond fixed discs, networked time sync.
