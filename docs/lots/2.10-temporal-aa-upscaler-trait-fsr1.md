# Lot 2.10 — Temporal anti-aliasing, Upscaler trait, render scale, FSR 1
- Model/effort: Sonnet, high | Depends on: 2.9 | Milestone: J2 (low-poly lit scene with sky, weather and FSR 1 on the host PC)

## Goal
Add one `Upscaler` trait, a render-scale system, temporal AA and FSR 1 (WGSL port) so the scene is rendered at a lower internal resolution and shown sharp at output resolution without motion trails.

## Crates
- Owns: `upscale` (create it if absent). Depends on `render`.
- May add WGSL sources (EASU, RCAS, TAA) under `shaders/` only if the public API of `shaders` stays unchanged.
- Read-only: `render` (pass list, `FrameCtx`, `ImageHandle`), `core`.
- Forbidden: changing the public interface of `render`, `shaders` or `core`. If needed, stop and report.
- `unsafe` is allowed in `upscale` (not needed in this lot). Errors: `thiserror`. Logs: `tracing`.

## Spec
Frame pass order (lot 2.2 and 2.9 provide passes 1-5 and 7): opaque, sky, transparents/particles/weather (reactive mask), AO and outlines, **upscaling or AA on HDR colour (pass 6)**, bloom/tonemapping/grading/screen effects (pass 7), viewmodel (pass 8), UI at display resolution (pass 9).
Jitter and motion vectors already exist (lot 2.2): Halton bases 2 and 3, 16 samples, added to the projection; motion vectors `RG16F` from current and previous *unjittered* positions, per-instance previous matrix. Consume them, do not recompute.
```
j_k = \frac{2\,(H_k - 0{,}5)}{\text{r\'esolution}} \qquad \vec{m} = \tfrac{1}{2}\left(\frac{c_{xy}}{c_w} - \frac{c'_{xy}}{c'_w}\right)
```

Trait (plan section 11, verbatim):
```
pub trait Upscaler {
    fn render_extent(&self, display: Extent2D, quality: Quality) -> Extent2D;
    fn jitter(&self, frame_index: u32) -> Vec2;
    fn execute(&mut self, ctx: &mut FrameCtx, inputs: &UpscaleInputs) -> ImageHandle;
}
```
`UpscaleInputs`: HDR colour before tonemapping, depth, motion vectors, jitter, exposure, frame time, near and far planes, field of view, reactive mask, reset flag (raised on respawn and teleport).

Implementations in this lot: Native (100 % scale, no upscale), TAA, FSR 1. Native and TAA run on every platform; FSR 1 runs everywhere.
- Quality levels (factor per axis, render size = output / factor): Quality 1.5, Balanced 1.7, Performance 2.0, Ultra Performance 3.0.
- Free render scale 50 % to 100 % is available for Native and FSR 1 only.
- TAA: reproject history with motion vectors; clamp history to the 3 × 3 neighbourhood bounding box in YCoCg; blend the current sample at 10 %. Reset history when the reset flag is set.
- FSR 1: WGSL port of two passes, EASU (edge-adaptive spatial upsampling) and RCAS (robust contrast-adaptive sharpening). Purely spatial.
- At startup, detect which upscalers are usable (registry returning a list of available modes). Any failure falls back to FSR 1.
- Interface, grain and vignette are applied after upscaling, at display resolution.
- FXAA (lot 2.9) remains the fallback anti-aliasing without temporal component.

## Public interfaces to create or respect
- `upscale::Upscaler` trait, `upscale::UpscaleInputs`, `upscale::Quality` enum (Quality, Balanced, Performance, UltraPerformance, Native, with free scale; name as in the plan trait), registry returning usable modes.
- Lots 2.11 and 2.12 implement the same trait without changing it.

## Acceptance criteria
- `cargo xtask ci` passes in Docker.
- Unit tests: render extent equals output divided by factor (rounded), free scale clamped to [50 %, 100 %]; TAA history is discarded when the reset flag is set; registry falls back to FSR 1 when an upscaler reports failure.
- `cargo xtask render-test`: the low-poly scene at FSR 1 for each quality level matches its reference image within tolerance; moving-camera frames show no ghosting trails (reference comparison).
- Zero validation-layer messages on lavapipe.
- Build for `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu` succeeds.
- Manual check on the host (not a gate): J2 scene from `dist/` shows a sharp upscaled image.
