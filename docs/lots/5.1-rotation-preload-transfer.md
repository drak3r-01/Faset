# Lot 5.1 — Rotation, preloading, map transfer by fingerprint
- Model/effort: Sonnet, medium | Depends on: 3.3, 4.7 | Milestone: none

## Goal
The server switches maps every 5 minutes, preloads the next map, and clients lacking that map download it by fingerprint.

## Crates
- Owned: `server` (rotation module), `client` (map loading and local cache).
- Read-only: `mapfmt` (format, validator, BLAKE3 fingerprint), `protocol` (`MapChange`, channel 3), `net`, `sim`, `minigame-api`, `mode-fps`, `core`.
- Forbidden: changing the public interface of any read-only crate. If a message or function is missing there, stop and report.

## Spec
Rotation timer:
- The match timer ends the match at `rotation_seconds = 300` (default; configurable in `server.toml` and by `clap` CLI flag).
- During the last 30 s, the server prepares the next map in a separate worker thread: read, validate, collisions, navigation graph. The dedicated server runs load steps 1, 3 and 4 only (read/migrate/symmetry/prefabs, collisions, navigation graph); meshes and height map are client-only.
- Scoreboard shown for 8 s between maps.
- Server sends `MapChange` carrying the map id and BLAKE3 fingerprint.
- Client loads the map from its map folders or cache. Unknown fingerprint: download on channel 3 (reliable, chunked), compressed. Chunk payload at most 1200 bytes (section 6); downloadable map at most 256 KB. The plan names no compressor: decision, pure-Rust, chosen in the lot and recorded in the report. After decompression the client recomputes the fingerprint; mismatch = reject and report error.
- Server waits until all clients report ready, at most 10 s, then starts warm-up. Clients not ready after 10 s do not block.
- Order: sequential, or random without repetition (a cycle covers all maps before any repeat). A vote among 3 maps is a later option, not this lot.
- Network file names are never used as paths; the fingerprint is the cache key.

Other constraints: map load budget < 2 s (section 20).

## Public interfaces to create or respect
- `server`: rotation config (`rotation_seconds: u32`, default 300) and order enum (`Sequential`, `RandomNoRepeat`).
- `client`: map cache keyed by fingerprint; `MapChange` handler; download progress event.
- Use existing `protocol` messages only.

## Acceptance criteria
- `dev.ps1 test` passes new tests:
  - rotation fires at 300 s on a simulated clock; preparation starts at 270 s;
  - a client without the map receives it on channel 3 and loads it; a tampered payload is rejected by fingerprint check;
  - a client not ready after 10 s does not block warm-up;
  - random order produces no repeat until all maps have been played.
- `dev.ps1 ci` passes.

## Out of scope
- Map vote; map editor; new map content; host migration.
