# Lot 6.3 — Classes and equipment, budget, preview, server validation
- Model/effort: Sonnet, medium | Depends on: 6.1, 4.6 | Milestone: none

## Goal
Players build a loadout within a point budget, see it in 3D, and the server rejects or replaces any invalid class.

## Crates
- Owned: `ui` (Loadout screen), `client` (`profile.ron` persistence).
- Read-only: `mode-fps` (class catalogue and validator from lot 4.6), `minigame-api`, `server`, `core`.
- Forbidden: changing public interfaces of read-only crates. If the server needs a validation entry point that does not exist, stop and report.

## Spec
- Flow: pick a base class, then primary weapon, secondary weapon, melee and gadget among those the class allows.
- A point budget limits combinations so custom classes stay balanced. The plan does not fix the budget value; define it as a constant in the mode's RON data, pick a value, and record it in the report.
- Colours chosen from a palette, with a 3D preview of the character.
- Storage: `profile.ron` in the data folder (classes).
- Server: revalidates every class received; an invalid class is replaced by the default class (Trooper).

Base classes (indicative for a time-to-kill of 0.4 to 0.8 s, tuned in 4.6 with `xtask balance`, section 16):
```
\mathrm{TTK} = \left(\left\lceil \frac{\mathrm{PV}}{D} \right\rceil - 1\right) \cdot \frac{60}{\mathrm{rpm}}
```

## Public interfaces to create or respect
- `client`: `Profile` (RON, versioned), `Loadout` value type with `budget_cost()`.
- `ui`: loadout view with budget meter and preview request.
- Server-side check uses the validator exported by `mode-fps` (lot 4.6): `validate_loadout(&Loadout) -> Result<(), LoadoutError>`.

## Acceptance criteria
- `dev.ps1 test` passes:
  - a loadout over budget is refused by `validate_loadout`;
  - the server replaces an invalid class with Trooper and sends back the replacement (protocol test with a crafted message);
  - `profile.ron` round-trips with the same content and version;
  - every base class in the table validates.
- `dev.ps1 render-test`: preview renders on lavapipe without validation errors.
- `dev.ps1 ci` passes.

## Out of scope
- Balance tuning (lot 4.6); new weapons or gadgets; settings screens.
