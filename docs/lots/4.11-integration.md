# Lot 4.11 - Phase-4 integration through the real server (internal lot)

Not in the reference plan. Opened after phase 4 because the phase-4 pieces
(controller, zones, modes, weapons, bots) only met in test harnesses: no lot
owned `server`, `client`, `protocol`, `minigame-api` and `dedicated` together.

- **Branch:** `lot/4.11-integration`
- **Owns:** `server`, `client`, `protocol`, `minigame-api`, `dedicated`.
- **Additive changes allowed in:** `sim`, `mode-fps`, `bots` (listed below).

## Goal

The phase-4 gameplay runs through `Server::tick`, the network protocol and
predicting clients instead of headless harnesses.

## What was done

1. **Controller on the real path.** `Server` builds its world with
   `World::with_controller` (`ServerConfig::move_params`, map zones in
   `MapConfig::zones`). Snapshot velocities are the controller's own.
   `client::Prediction` runs the same controller: each history entry keeps
   the full `controller::PlayerState`, the `ZoneTracker`, the frozen flag and
   the speed multipliers; a correction restores the predicted full state of
   the confirmed tick with the snapshot's position, velocity and ground flag,
   then replays. The 1.6 / 1.10 tests pass on the controller.
2. **Hosted match.** `Server::host_match(Match)`: every player joins it; each
   tick it runs after the world step with the tick's commands, zone events
   and `ModeServices` (lag compensation); respawn requests teleport players
   (`World::teleport`), effects push them (`World::add_velocity`) or scale
   their speed (`World::set_move_scale`); movement is frozen outside
   `Warmup`/`Playing` and for dead players; snapshots carry the mode's
   health and alive flag; the match state, events and messages go to every
   client on the event channel; clients' mode messages reach the mode.
3. **Framework hooks.** `GameMode::on_client_message`, `GameMode::vitals`,
   `GameModeClient::vitals` / `move_scale` (all with defaults),
   `SpawnPoints::request`, `ModeCtx` command/zone/host/pickup/timer access
   and push/scale requests, `HudCtx` match fields, client-side
   `MatchMirror`, wire layout of `GameEvent`.
4. **FPS modes wired.** `FpsRules::command` dispatches by `WeaponKind`
   (hitscan with lag compensation, projectiles with the live
   `ProjectileSystem` and catch-up, melee on rewound hitboxes), handles the
   weapon slot, reload and auto-reload, kill volumes; blasts push players;
   class speed and timed bonuses become speed multipliers; `FfaMode` and
   `TeamMode` use the class `Catalog` (`ClassMsg` to choose a class).
5. **Bots as virtual clients.** `dedicated::fps_bot::FpsBot` wraps a
   `faset_bots::Bot`: it reads a `BotContext` (world, match) and returns an
   `InputCommand` through the normal command buffer; it sends its class as a
   mode message.

Acceptance test: `crates/dedicated/tests/fps_match.rs` (fps.team, two
predicting humans + four bots, memory transport, rockets, rifle, melee,
pickups, bot hits, twice for determinism). J1 (`dedicated/tests/j1.rs`),
J3 (`sim/tests/controller.rs`) and J4 (`bots/tests/duel.rs`) still pass.

## Decisions

- **Fire input:** one path for humans and bots: `faset_protocol::BUTTON_FIRE`
  (bit 2, the bit 4.10 reserved), plus `BUTTON_SIGHT` (bit 3) and
  `BUTTON_RELOAD` (bit 4). A fresh press is the fire bit set now and not in
  the previous command. `FireMsg` stays defined but is not sent.
- **View instant of a shot:** commands carry no view tick, so the server
  rewinds a human's shot by its round trip plus `faset_server::VIEW_DELAY`
  (0.1 s of interpolation); bots shoot at the present.
  `LagCompensation::resolve_view_time` still clamps.
- **Protocol version 2.** New `Event` variants: `MatchState`, `Game`,
  `Mode` (opaque, at most `MAX_EVENT_BYTES` = 1100) and typed
  `ProjectileSpawn` / `Explosion` (the 1.5 gap). `Event`/`Message` lost `Eq`
  (floats).
- **Match state replication:** sent on join and, when its bytes changed, at
  the snapshot rate.
- **Client messages** are delivered to the mode at the start of the next
  match tick, any phase.
- **Correction restore:** predicted full state + snapshot position,
  velocity, ground flag (the snapshot holds nothing else).
- **Snapshot deltas:** a changed position axis travels as a 12-bit
  difference (±4 m) and a velocity axis as an 8-bit difference (±8 m/s)
  when they fit, else in full: the controller's gradual turns pushed the
  1.10 downlink to 104 kbit/s; it is back under 100.
- **Classes:** default class `trooper`; slot 0 main weapon, slot 1 the
  chosen (or first allowed) secondary; a class choice applies at the next
  spawn, at once outside `Playing`. Class health and speed factor are used;
  class traits (double jump, resistance, scope...) are not.
- **Match start:** everyone is moved to a spawn point (round robin).
- **Kill volumes:** lethal self-damage (suicide score), still subject to
  spawn protection.
- **Map pickups:** `health`, `armor`, `ammo` map to heal, armour, ammo;
  weapon pickups are ignored.
- **Bots:** class cycles through the catalog by bot index; skill
  `bot_level` 0-2 Easy, 3-5 Normal, 6-8 Hard, 9-10 Expert; vitals/teams read
  from the hosted match; pickups always reported available; shots not heard.
- **Dedicated:** `game_mode` setting (empty by default = sandbox, which keeps
  J1 unchanged) and `seed`; maps load from `mapfmt` files; embedded maps
  `test-arena` and `example`.

- `editor` (merged meanwhile, lot 5.4): its test session fills the new

## Remaining gaps

- No reusable client session/app glue in `client`: the e2e test holds its
  own glue (handshake, prediction, `MatchMirror`); phase 6 needs a real one.
- Remote players are not rendered from the match (no client app yet); the
  HUD gets `HudCtx` match fields but `client::hud` is not fed from a live
  session.
- Lag compensation uses an estimated view instant, not the client's real
  interpolation time.
- Projectiles, knockback and teleports are not predicted on the client
  (server corrections; snapped for respawns).
- Class traits, weapon pickups, heard shots for bots, pickup availability
  for bots, late joiners' score table (only later `ScoreChanged` events),
  `say` and runtime `map` console commands are still open.
- Map rotation does not change the server's map at `MapChange` (the match
  cycles phases only).
