# Lot 6.10 - Terrain with relief (internal lot)

Not in the reference plan. The current terrain is made of blocky brushes and looks too angular. Goal: smooth, TF2-like terrain. Props and buildings may stay angular.

- **Model/effort:** Opus, high | **Depends on:** 6.8, 6.9 | **Branch:** `lot/6.10-terrain-relief` (one PR)
- **Owns:** `mapfmt` (terrain data), `sim` (terrain collision), `editor` (sculpting), `bots` (navigation on slopes), `client`/`render` (terrain mesh). Public interface changes of these crates are allowed for this lot only; document them in the report.

## Goal

Maps can have rolling ground, hills, banks and valleys that look smooth, play well, and are sculpted in the editor.

## Spec

1. **Map format:** optional heightmap/terrain layer (regular grid, metres, RON-friendly encoding; resolution is a decision), versioned and backward compatible with existing maps; validator rules for it.
2. **Mesh:** smooth normals, chunked mesh friendly to LOD/distance fade, slope-based texture blending (grass/sand/rock/snow per map theme, code-generated pixel style, our own palette).
3. **Simulation:** slope collision in `sim` for server and client prediction (deterministic, same code path), walkable slope limit, no jitter over triangles; existing replay traces unchanged; new terrain traces added.
4. **Bots:** navigation graph built on terrain (slope cost, unwalkable steepness).
5. **Editor:** sculpt tools (raise, lower, smooth, flatten, paint material), undo/redo, saved in the map file.
6. **Migrate** one existing map to the terrain as proof (full redesign is lot 6.13).

## Acceptance

`cargo xtask ci` green; determinism tests pass; no misprediction on slopes (test); bot trial on the migrated map completes; editor sculpt round-trip test.
