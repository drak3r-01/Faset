# Lot 1.8 — dedicated: configuration, console, clean shutdown, Docker image
- Model/effort: Sonnet, medium | Depends on: 1.4 | Milestone: J1 (reached after this lot)

## Goal
Ship the `dedicated` executable: headless dedicated server configured by `server.toml` and command-line flags, with an stdin console and clean shutdown, delivered in the `server-runtime` Docker image. It must not depend on any graphics or audio crate.

## Crates
- Owns: `dedicated`, and the `server-runtime` stage of the Dockerfile.
- Read-only: `server`, `sim`, `net`, `protocol`, `core`.
- External: `clap`, `toml`, `anyhow` (executable), `tracing`.
- Forbidden: every other crate. `dedicated` must not depend on `ash`, `winit`, `kira`, `render`.

## Spec
Configuration (section 7):
- File `server.toml` plus command-line arguments (`clap`). Arguments override the file.
- Settings: name, port (UDP, default 7777), maximum players, mode, rotation list, rotation duration (default 300 s), number and level of bots, password.
- Maps are read from a `maps/` folder next to the executable, in addition to the native maps embedded in the binary.

Console (stdin): `status`, `kick <player>`, `map <name>`, `say <text>`, `quit`.

Shutdown: clean stop on Ctrl+C (SIGINT) and on `quit`: notify clients, flush logs, exit code 0.

Docker image `server-runtime` (section 3 and 7): Debian slim containing only the `dedicated` binary, built in a multi-stage Dockerfile (build-stage layout is a lot decision; the plan only says Debian slim plus the binary). Publishes UDP port 7777.

Budgets (section 20): memory below 200 MB; server tick below 2 ms on one core with 16 players including bots.

## Public interfaces to create or respect
- Command-line interface and `server.toml` schema (documented, English).
- `dev.ps1 run-server` launches the server in its container with the UDP port published.

## Acceptance criteria
- `cargo tree -p dedicated` contains neither `ash` nor `winit` (automated test).
- `dev.ps1 run-server` starts the server in a container, with no graphics dependency.
- `docker build --target server-runtime` produces the image; the container runs it.
- Milestone J1 demo: two headless test clients connect to the dedicated server in the container and move, with 5 % packet loss.
- Console `status`, `kick`, `say`, `quit` work; SIGINT exits with code 0 after notifying clients (test or scripted check).
- `dev.ps1 ci` passes.

## Out of scope
Integrated server and LAN discovery (1.9), rotation logic beyond reading the settings (lot 5.x), password enforcement details beyond the field (report if missing), game modes.
