# Lot 2.1 — Vulkan instance, GPU choice, swapchain, frame loop, offscreen target
- Model/effort: Opus, moyen | Depends on: 0.3 | Milestone: none

## Goal
Create the `render` crate's Vulkan 1.2 device, a windowed swapchain frame loop, and an offscreen target that reads back to PNG for headless tests.

## Crates
- Owned: `render`.
- Read-only: `core` (typed ids, `glam`, `tracing`). Do not change `core`.
- Forbidden: all other crates (`sim`, `net`, `protocol`, `server`, `dedicated`, `ui`, `client`, ...).
- New dependencies in `render`: `ash`, `winit`, `gpu-allocator`, `thiserror`, `tracing`, `image` (PNG encode). Check licences with `cargo deny`.
- `unsafe` is allowed here (only `render` and `upscale` may use it); keep it in small wrapped blocks with `// SAFETY:` comments.

## Spec (condensed)
- Stack: `ash` for Vulkan, `winit` for the window, `gpu-allocator` for memory.
- Base API: Vulkan 1.2 with `VK_KHR_dynamic_rendering`. No geometry or tessellation shaders (MoltenVK lacks them).
- macOS only (`cfg(target_os = "macos")`): enable `VK_KHR_portability_enumeration` and `VK_KHR_portability_subset`; MoltenVK is embedded. Compile-check only here; real run is CI.
- GPU choice by score: discrete > integrated > software (lavapipe). Score function must be pure and unit-testable on a fake device list. Expose `GpuPreference { Auto, Index(u32) }` so a settings value can override it later (TOML reading is lot 6.4, not here).
- Swapchain: 8-bit sRGB format (pick an available `*_SRGB` BGRA/RGBA format). Present mode: vsync on -> FIFO; vsync off -> MAILBOX, else IMMEDIATE, else FIFO.
- Recreate swapchain on resize. Pause rendering while width or height is 0 (minimised).
- Two frames in flight. Each frame owns: command pool, uniform ring buffer, semaphores, fence.
- Destroyed resources go through a deferred queue that frees them two frames later.
- Offscreen: render into an image with no surface, copy back, write PNG.
- Validation: Khronos validation layers on in debug/test builds. Zero validation messages is an acceptance criterion.

## Public interfaces to create
- `pub struct RenderConfig { pub gpu: GpuPreference, pub vsync: bool, pub size: (u32, u32) }`
- `pub struct RenderWorld { pub clear_color: [f32; 4] }` — skeleton only; lot 2.2 extends it. Renderer never reads ECS; it only consumes `RenderWorld`.
- `pub struct Renderer` with:
  - `Renderer::new_windowed(window: &winit::window::Window, cfg: &RenderConfig) -> Result<Self, RenderError>`
  - `Renderer::new_headless(cfg: &RenderConfig) -> Result<Self, RenderError>`
  - `fn resize(&mut self, width: u32, height: u32)`
  - `fn render_frame(&mut self, world: &RenderWorld) -> Result<(), RenderError>`
  - `fn read_back_png(&mut self, path: &std::path::Path) -> Result<(), RenderError>` (headless only)
- `#[derive(thiserror::Error)] pub enum RenderError` (no `anyhow` in libraries).

## Acceptance criteria
- `cargo xtask render-test` passes in Docker (lavapipe): a headless 256x256 frame with a known clear colour is read back and matches `render/tests/refs/clear_256.png` with max error 1 per channel.
- Same test asserts zero validation messages (count them through a debug messenger).
- Unit test: GPU score ordering discrete > integrated > CPU on a fake device list; present-mode selection covers vsync on/off.
- Unit test: resize to 0x0 does not panic and skips frames.
- `cargo xtask build --target x86_64-pc-windows-msvc` and `--target x86_64-unknown-linux-gnu` succeed.
- Manual on host (report result): copy the Windows client to `dist/`, the window opens, resizes, and minimise pauses rendering.

## Out of scope
Meshes, shaders (WGSL), depth buffer use, camera, lighting, MoltenVK run (CI), settings file parsing, upscaling, `RenderWorld` contents beyond `clear_color`.
