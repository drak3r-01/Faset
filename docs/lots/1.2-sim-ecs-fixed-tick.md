# Lot 1.2 — sim: ECS world, fixed tick, system order, base collisions
- Model/effort: Opus, medium | Depends on: 1.1 | Milestone: none

## Goal
Build the deterministic fixed-step simulation world in `sim` (hecs ECS, fixed tick, ordered systems, base collision queries) so that a recorded input trace replays bit-identically.

## Crates
- Owns: `sim`.
- Read-only: `core`, `protocol` (quantizers, `Tick`, `NetId`). `mapfmt` does not exist yet (phase 3): use test volumes built in code.
- External: `hecs`, `parry3d`, `glam`, `proptest` (dev).
- Forbidden: every other crate.

## Spec
Fixed step (section 5): simulation advances in steps of 1/60 s, same code on client and server.
```
acc += frame_dt.min(0.25);          // avoid spiral of death
while acc >= DT { step(); acc -= DT; }
let alpha = acc / DT;               // render = lerp(prev, curr, alpha)
```
Ordered systems in one tick:
1. Read the input commands of the tick.
2. Player movement (section 15; stub in this lot).
3. Weapons and firing (section 16; stub).
4. Projectiles.
5. Damage and deaths.
6. Pickups and zones.
7. Game mode rules (`minigame-api` later; hook only).
8. Respawns.
9. Record collision history (server only; hook only, used by lot 1.7).
10. Emit snapshot (server, every other tick; hook only).

Components: `Transform`, `Velocity`, `PlayerState` (on ground, slide, timers), `Health`, `Inventory`, `WeaponState`, `Projectile`, `Pickup`, `Team`, `NetId`, `Owner`. ECS is `hecs`. `NetId` (`u16`, assigned by server) is distinct from hecs entity ids.

Collision world:
- Static map = set of convex volumes (boxes, ramps, cylinders, prisms) in a bounding-volume tree, using `parry3d`.
- Player = vertical capsule, radius 0.35 m, height 1.8 m; height 1.0 m while sliding.
- Three queries required: ray cast, shape cast (sweep), intersection test (overlap).

Determinism rules:
- Inputs are quantized (lot 1.1 quantizers) before simulation on both sides.
- Random numbers: PCG, seeded from (server seed, player, shot counter). The client can reproduce its own spread exactly.
- No iteration over hash tables in the simulation. Iterate by ascending `NetId`.
- Floats are not bit-identical across x86 and ARM. Reconciliation (lot 1.6) tolerates 1 cm position and 5 cm/s velocity before correcting.

## Public interfaces to create or respect
- `World` with a constructor taking a seed, and `step(inputs)` advancing one tick.
- Trace recorder: stores per-tick inputs, and state (positions and a state hash) so a trace can be replayed.
- Collision API: ray cast, shape cast, intersection on a static volume set.

## Acceptance criteria
- A reference trace (committed under the crate's test data) replayed in a fresh process gives identical final positions and state hash (test).
- Proptest: a capsule swept against a box never penetrates it (no penetration beyond a small epsilon, document it).
- `rg -n "HashMap" crates/sim/src` returns nothing (use `BTreeMap` or `Vec` instead).
- `#![forbid(unsafe_code)]` in `sim`.
- `docker compose run --rm dev cargo xtask test` passes.

## Out of scope
Real movement equations (section 15, lots 4.x), weapon logic (section 16), map loading (`mapfmt`), networking, bots.
