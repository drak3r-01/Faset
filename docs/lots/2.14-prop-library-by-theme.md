# Lot 2.14 — Prop library by theme (about 150 recipes)
- Model/effort: Haiku, low | Depends on: 2.13 | Milestone: none

## Goal
Write about 150 validated prop recipes across nine themes, in several sessions, with no code change.

## Crates
- Owns: data files only, `assets/props/<theme>/<name>.ron` (suggested path; the plan does not fix it, report if changed).
- No Rust code. Forbidden: any change to `assets` or `asset-tool` code.
- If a recipe needs a primitive or operation that lot 2.13 does not provide, stop and report. Do not work around it.

## Spec
- Nine themes, one directory each: `urban`, `industrial`, `nature`, `desert`, `snow`, `space`, `underwater`, `neon`, `interior`.
- Each theme covers three kinds of props: cover, obstacles and decoration. Target about 16 to 17 recipes per theme, about 150 in total.
- File names and recipe names in English, kebab-case.
- Each recipe uses only primitives and operations from lot 2.13, with palette names for colours (`wood`, `metal`, `accent1`, ...). No hard-coded colour values.
- Triangle budget per prop: 20 to 200.
- Collision declared on every recipe: `none`, `box`, `convex hull` or `compound`.
- Use a `seed` for variants where useful (tree height, rock shape).
- Work one theme per session. Validate after each theme.

## Public interfaces to create or respect
- Recipe format defined by lot 2.13. Do not change it.

## Acceptance criteria
- Exactly nine theme directories exist with the names above.
- Total recipe count between 140 and 160.
- `asset-tool validate assets/props` passes with zero errors.
- Every recipe is within its triangle budget (reported by the validator).
- A contact sheet per theme is generated and reviewed visually; the review result is in the report.
- `cargo xtask ci` passes in Docker.

## Out of scope
- Code changes of any kind.
- New primitives or operations.
- Maps, characters, weapons, audio.

## Session protocol
1) Read CLAUDE.md and this file.
2) Do not use graphify until the repo has Rust code; then query it (`graphify query "<question>"`) before grepping.
3) Branch `lot/2.14-prop-library-by-theme`, one branch per theme session is acceptable only if all themes end in one PR. All commands run in Docker, never on the host.
4) Run `cargo xtask ci` in Docker before merge (local gate; GitHub CI only runs on tags).
5) Conventional Commits in English; one lot = one branch = one PR; run `graphify update .` once code exists.
6) Short report: count per theme, validator result, deviations.
