# Lot 4.5 — Projectiles, explosions, melee
- Model/effort: Sonnet, medium | Depends on: 4.4 | Milestone: none

## Goal
Add projectile weapons, area explosions with knockback (including the self-explosive jump) and melee to the shot pipeline of lot 4.4.

## Crates
- Owned: `mode-fps` (projectile and explosion systems, melee hit test, tests).
- Read-only: `sim` (collision sweeps, raycast, character controller), `minigame-api`, `protocol`, `server`/`net` (existing public API only), `core`.
- Forbidden: changing public interfaces of `sim`, `minigame-api`, `server`, `net`, `protocol`, `core`. Stop and report if needed.

## Spec
### Projectile integration
Per tick (dt = 1/60 s) with gravity g (vector) and quadratic drag k_d:
a = k_g * g - k_d * |v| * v; v <- v + a*dt; p <- p + v*dt.
Without drag the trajectory is exact: p(t) = p0 + v0*t + 1/2 * k_g * g * t^2.
Collision sweeps a sphere (radius from weapon) from the current to the next position, so a fast projectile never crosses a wall. Bounces: count from the weapon definition; each bounce reflects v about the surface normal (restitution is not given in the plan: a RON field, value chosen by the session and reported). Lifetime in seconds; expires on timeout.
Weapon fields used: speed, gravity factor k_g, drag k_d, radius, lifetime, bounces, explosion radius R, explosion knockback K.

### Network model
Client: shows a visual projectile immediately, simulated locally.
Server: creates the real projectile at the command tick and advances it by half the shooter's latency, capped at 100 ms.
Replication: no per-frame projectile state. The server sends a creation event (origin, velocity, tick, seed); each client simulates it locally.
Contacts are resolved by the server only, in the present.

### Explosions
Damage and knockback fall with distance d from the centre, for d < R:
D(d) = D0 * (1 - d/R)^p; delta_v = u_hat * K * (1 - d/R), where u_hat points from centre to the target.
A raycast from the centre to the target must be unobstructed by walls; otherwise no damage or knockback.
Self-damage is halved; self-knockback is kept, which enables the explosive jump (Boomer class).
Expected jump: an upward delta_v of K*(1 - d/R) applied to the player at distance d from the blast centre; the resulting apex follows the controller's gravity (g = 20 m/s^2).

### Melee
Weapon type `Melee`: short-range hit test against rewound hitboxes (lot 1.7 history), same damage chain as lot 4.4. Melee range, arc and cooldown are data fields. The plan gives no numeric values: choose them in RON and report them.

## Public interfaces to create or respect
- Extend the `WeaponDef` of lot 4.4 with the projectile block (`ProjectileDef`) and the explosion block (`ExplosionDef`), both serde, RON.
- Pure functions: `step_projectile(state, dt, env) -> ProjectileStep`, `explosion_effect(centre, target, def, world) -> (damage, delta_v)`. Time and randomness passed explicitly.
- Creation event type for replication (origin, velocity, tick, seed). Its wire layout is owned by `protocol`: use the existing message types only; if a new message is required, stop and report.

## Acceptance criteria
- `cargo xtask test`:
  - `explosive_jump_matches_formula`: a blast at a player's feet yields the delta_v of the formula, and the simulated apex matches the analytic apex within 1 cm.
  - Self-damage equals half the damage to others at the same distance.
  - Wall between centre and target blocks damage and knockback.
  - Drag-free projectile position after N ticks matches p(t) within 1 mm.
  - A projectile moving 60 m/s never tunnels through a 0.2 m wall.
  - Bounce count and lifetime expiry are respected.
- `cargo xtask ci` is green.
